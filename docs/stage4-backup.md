# Этап 4. Резервное копирование

## 1. Цель и роль резервного копирования

На четвёртом этапе реализовано резервное копирование критичных конфигураций инфраструктуры.  
Цель — обеспечить восстановление после сбоев и сохранить ключевые данные:

- конфигурации PKI (CA);
- конфигурации OpenVPN;
- конфигурации мониторинга (Prometheus/Alertmanager).

Бэкапы выполняются автоматически по расписанию через systemd timer.

---

## 2. Инфраструктура и размещение

- Облако: Yandex Cloud.
- ОС: Ubuntu 24.04 LTS.
- Отдельная ВМ `vm-backup` (рекомендуется), в той же VPC, что и остальные узлы.

При необходимости допускается запуск на `vm-monitor`, но предпочтительна отдельная ВМ.

---

## 3. Скрипты автоматизации (scripts/)

Скрипты Stage4 находятся в `scripts/` и устанавливаются в `/usr/local/sbin` при запуске `bootstrap.sh`.

### 3.1. stage4_run_backup.sh

Назначение: непосредственное выполнение бэкапа.

Основные действия:

- формирует архив `/var/backups/devops-final/devops-backup-<timestamp>.tar.gz`;
- включает в архив существующие каталоги:
  - `/etc/pki`;
  - `/etc/openvpn`;
  - `/etc/prometheus`;
  - `/etc/alertmanager`;
- создаёт SHA-256 checksum (`.sha256` файл);
- выполняет ротацию: хранит последние 7 архивов.

Скрипт работает идемпотентно и пропускает отсутствующие каталоги.

---

### 3.2. stage4_configure_backup.sh

Назначение: настройка автоматических бэкапов через systemd.

Основные действия:

- создаёт unit-файл `/etc/systemd/system/devops-backup.service`;
- создаёт таймер `/etc/systemd/system/devops-backup.timer`;
- включает и запускает таймер (`OnCalendar=03:30`, ежедневный запуск).

Запуск через bootstrap:

```bash
cd ~/devops-final-pki-ca/scripts
sudo ./bootstrap.sh stage4
```

---

## 4. Проверка работоспособности Этапа 4

Автоматическая проверка:

```bash
cd ~/devops-final-pki-ca/scripts
sudo ./bootstrap.sh stage4-verify
```

`stage4-verify` проверяет:

- активность `devops-backup.timer`;
- наличие архивов в `/var/backups/devops-final`.

Ручная проверка:

```bash
ls -lh /var/backups/devops-final
systemctl status devops-backup.timer
```

## 5. Связь с другими этапами

- Этап 4 архивирует результаты Этапов 1, 2 и 3.
- Мониторинг Этапа 3 может отслеживать выполнение бэкапов (например, через Node Exporter + custom checks).
